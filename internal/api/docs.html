User form and ready configurations

Panel labels are not JSON field names. Resource paths use the returned opaque user id, not the username. Owner/node tokens can create manual accounts with POST /users; reseller-bound tokens provision through assigned templates on POST /purchases.

Form controlREST input and behavior
Username / accountusername: immutable, globally unique ASCII letters, digits, underscore or hyphen, 3–32 characters. Soft deletion keeps it reserved.
Template / Customtemplate_id: enabled technical template ID, or absent/null for manual terms. On create, saved terms override manual limits, duration, start policy and profile. PATCH changes only the reference.
Traffic volumetraffic_limit_bytes: exact bytes. Preset buttons and the GB/MB selector are panel shortcuts.
Device limit / Maximum devicesdevice_limit: positive registered-config cap or null for unlimited; includes disabled devices. It does not allocate configs or measure simultaneous connections/hardware IDs. Lowering it does not delete devices.
Create ready devices with accountPOST /purchases with device_count: 1–100, default one for absent/null, within the account cap. Independent keys and addresses; all requested devices, account, link and recoverable result commit together. POST /users and bulk creation create no devices or link. There is no auto_devices JSON input.
Duration / Start policyduration_seconds and create-only start_policy (immediate default, or first_connection). User/template PATCH absent/null duration leaves it unchanged; a value does not recompute user expiry.
Exact dateNo create/PATCH expires_on or expires_at input. Owner/node integrations use POST /users/{id}/renew with {"mode":"exact","exact":"2026-10-30T12:00:00Z"}; this is a separate operation, not atomic exact-date creation.
Notenote: internal text with JSON \n line breaks. PATCH empty string clears it; absent/null keeps it.
Interfaceinterface_id: ID, not name. Device selection uses explicit profile, user profile, then first enabled interface in name order. User edits do not move existing devices.
Download / Upload speedspeed_limit_down_kbps / speed_limit_up_kbps: panel MB/s × 8,000. Independent caps aggregate across devices on an interface.
Tagstags: JSON array such as ["vip","telegram"], not comma-separated text. PATCH [] clears; absent/null keeps existing tags.
Display name / Enabled / Annotationsdisplay_name is separate from identity; enabled is boolean (default true); status is derived. metadata is stored at creation; the current PATCH handler does not persist metadata updates.

For three ready configs, send this JSON to POST /api/v1/purchases with a scoped Bearer token and required Idempotency-Key:

{"username":"customer123","device_count":3,"entitlement":{
  "traffic_limit_bytes":100000000000,"duration_seconds":2592000,"device_limit":3
}}

A reseller sends {"template_id":"assigned-template-id","device_count":3}. The assigned enabled template must permit that count. Results return device_ids in creation order and device_id for the first item. Read each private config/QR with configs.read, or the customer link with subscriptions.read. Multiple labels default to device-1, device-2, etc.; a custom device_name becomes the prefix. Final names must be 1–64 UTF-8 bytes. Replay returns the same IDs; a changed count under the same key returns 409. Old saved single-device results can omit the array. Any provisioning failure rolls back the complete purchase; commit does not certify runtime reconciliation or a live handshake.

The panel's auto-create shortcut remains separate: at most 10 devices after user creation, with per-device transactions and possible partial completion. Ordinary POST /users/{id}/devices creates one device and has no idempotency replay middleware. Disabled devices occupy slots; deleting a device frees its slot. Creation at/above the cap returns DEVICE_LIMIT_REACHED.

Bulk requests have their own documented field sets: shared note/display-name/tags and terms for creation; restricted update fields and per-user outcomes for actions. add_traffic increases charged usage; quota/add increases allowance. traffic/reset resets charged usage.

Panel-only management includes administrator/reseller and token creation, permission assignment, account restore, dedicated link revoke/restore, all-config ZIP download, backup/restore, host update control and browser appearance preferences. Do not infer REST paths for these actions. Settings exposed by /settings are separate from per-browser preferences. Webhooks are optional: polling works without them. Scopes do not override reseller ownership/route restrictions.

Units

QuantityAPI unit and conversion
Traffic quota, usage and top-upInteger bytes. Panel MB/GB are decimal: 1 MB = 1,000,000 B; 1 GB = 1,000,000,000 B.
Speed limitsspeed_limit_down_kbps and speed_limit_up_kbps use kilobits/s: 1 Kbps = 1,000 bits/s. Mbps × 1,000; panel MB/s × 8,000.
Live transfer rates*_bytes_per_second are B/s. Divide by 1,000,000 for MB/s; multiply by 8 then divide by 1,000,000 for Mbps.
Durationduration_seconds is seconds. 30 days = 2,592,000 s; the panel's month shortcut means 30 days.
TimestampsRFC3339 instants; responses use UTC (Z).
Uptime / cadence / online windowSeconds. Node uptime is WG-Guard process uptime; telemetry uptime is host uptime.
Memory / disk / process sizeInteger bytes; the same decimal MB/GB conversion applies.
CPU / memory / disk utilizationPercent on a 0–100 scale: 25 means 25%. load_1 is a dimensionless one-minute task load average.
Device limits / counts / pagination / attemptsInteger counts of configurations, entities, samples or delivery attempts.
Networkmtu is bytes; listen_port is a UDP port number; subnet prefixes such as /24 are bit counts.

For 100 GB, send "traffic_limit_bytes": 100000000000. 100 GiB is 107374182400 bytes and displays as 107.4 GB. The API preserves exact bytes; display rounding does not change the quota. When creating with template_id, the template's saved terms override manual limits.

For 100 Mbps download, send "speed_limit_down_kbps": 100000; the panel speed form shows 12.5 MB/s. For 20 Mbps upload, send "speed_limit_up_kbps": 20000, equivalent to 2.5 MB/s. A byte is eight bits. These are limits, not guaranteed throughput. Omit an optional direct-purchase speed field for unlimited.

RX is measured at the server: client→server (customer upload). TX is server→client (customer download). Charged quota includes both directions. Traffic-series rx/tx are byte amounts for the bucket, not speeds. Unavailable telemetry is null; measured zero is 0.

Durations: 1 hour = 3600, 1 day = 86400, 7 days = 604800, 30 days = 2592000, 90 days = 7776000 seconds. The configured duration starts at creation for immediate, at the first observed connection for first_connection, or at activation for a queued Next Plan.

Renewal: from_now uses now + duration; from_expiration uses max(now, current expiry) + duration; exact uses an RFC3339 date with timezone, such as 2026-10-30T12:00:00Z. Localized calendar dates and Unix milliseconds are not date-time inputs. The webhook signature's t is Unix seconds; its JSON timestamp is RFC3339.

Settings use their key's unit: _gb is decimal GB; _months is fixed 30-day periods; _seconds, _hours and _days are time units; retention/attempt counts are counts. network.client_persistent_keepalive is seconds in the pinned string format 0, N or N-M. The API rate limit is requests per 60-second window; Retry-After on 429 is seconds.

Where allowed, null quota/speed/device limits mean unlimited. REST user/template traffic_limit_bytes: 0 is a finite zero-byte allowance; speed/device limits must be positive or null. Direct purchases require positive finite quota, duration and device limits. PATCHing duration_seconds changes the stored term; use renewal to change an existing expiry.

Limits are tri-state: a speed-limit field left absent defaults to unlimited on create; null on update clears it to unlimited — download (server→client) and upload (client→server) are independent. Mutating endpoints accept Idempotency-Key. Replay applies only to the operations documented as idempotent; ordinary device creation and access rotation do not gain replay behavior by receiving that header. Errors: one envelope with a stable error.code.
