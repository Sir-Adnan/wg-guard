# Phase 8.2 Secure Access & Persistent Manager Implementation Plan

Status: **executed and complete on 2026-09-09**. Verification and residual limits are recorded in
[`docs/development/phase8.2.md`](../../development/phase8.2.md).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver a cached state-aware host manager plus safe domain, Nginx, DNS-01, IP-certificate, manual, and private panel exposure that can be reconfigured and recovered after installation.

**Architecture:** Keep the Go binary as the lifecycle owner and retain the runtime's existing TLS modes. Add installer-only exposure/certificate intent, deterministic host artifacts, optional Certbot execution, and transactional Nginx/reconfiguration services; the Bash entry only acquires and persists a verified manager.

**Tech Stack:** Go 1.25+, stdlib, existing terminal/config/install packages, Bash/Python bootstrap fixture, Ubuntu 24.04 systemd, Docker Compose, Nginx, Certbot snap and certbot-dns-cloudflare snap.

**Spec:** `docs/development/phase8.2.md`

## Global constraints

- Supported production host is Ubuntu 24.04 or newer on amd64/x86_64; Ubuntu 24.04 is the required real-host gate.
- Terminal UI is English-only; web fa/en catalogs remain unchanged except shared-key parity where necessary.
- Never expose production HTTP publicly, stop an unknown listener, overwrite a foreign proxy block, or place a token/key/password in argv, logs, state, or evidence.
- New Go modules are forbidden for this phase; Certbot is optional and invoked from `/snap/bin/certbot` only for explicitly selected strategies.
- Every production behavior starts with a failing test, then the minimal implementation, then refactoring while green.
- No REST/OpenAPI change is expected; update it only if implementation changes the API contract.
