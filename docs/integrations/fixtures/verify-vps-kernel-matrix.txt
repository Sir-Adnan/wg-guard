AmneziaWG runtime parameter verification matrix — REAL VPS kernel module
========================================================================

Environment (2026-08-31):
  Ubuntu 24.04 LTS (noble), KVM guest, kernel 6.8.0-137-generic, x86_64
  amneziawg-tools v3.1.20260812 + amneziawg-dkms 1.0.0 (PPA ppa:amnezia/ppa, native noble build)
  Kernel module "amneziawg" (module name is amneziawg, NOT awg: `modprobe amneziawg`)
  Link creation: `ip link add awg0 type amneziawg`
  Keys below are single-use throwaway test keys (redacted where irrelevant).

Setconf format requirement
--------------------------
  `awg setconf` REJECTS headerless configs ("Line unrecognized: `PrivateKey=…`") —
  stock wg tolerates lines before any [Interface]/[Peer] header, tools v3.1 does not.
  WG-Guard's renderer always emits explicit section headers (unaffected).
  `awg-quick strip` uses shell/awk text processing, not the C parser, so it still
  accepts headerless input — not a counterexample.

HeaderProtectionKey coupling (kernel-enforced)
----------------------------------------------
  hpk + coherent S1/S2/S3/S4 (plain H)     rc=0, hpk round-trips
  hpk WITHOUT S3/S4 (plain H / H ranges / + RandomTrailers)  rc=1 Invalid argument
  hpk written incrementally AFTER S3/S4 persist from a prior setconf
                                           rc=1 Invalid argument  (must be SAME setconf)
  hpk rotation (new key) with S3/S4 in the same conf        rc=0
  => SOURCE RULE: HeaderProtectionKey requires ALL S1-S4 to be >= 12. This runtime matrix also
     demonstrates that S3/S4 must be present in the same setconf message in the tested path.
     WG-Guard must render and validate one coherent S1-S4 + HPK block.
  hpk clearing ("(none)") is parser-rejected; setconf cannot unset HPK (omitted
  keys persist) — removing it requires link recreate.

Clearing / partial-set semantics (kernel)
-----------------------------------------
  S3=0/S4=0 clear attempt with HPK set ..... rc=1 (violates HPK⇒S3/S4), values persist
  H1..H4=0 clear attempt .................. rc=1, ranges persist
  Jc=0 alone .............................. rc=0 (jc=0 legal; junk disabled), Jmin/Jmax kept
  omitted keys persist across setconf ..... rc=0 verified on kernel
     (port 51820→51821 while S3/H-ranges/padding/flags all kept)
  fresh interface dump defaults ........... H1..H4 = 1,2,3,4 (stock header values),
     everything else 0/off/(null)/(none)

WG-Guard consequences (implemented in this pass)
------------------------------------------------
  - render.go: a coherent S1-S4 block is emitted with HeaderProtectionKey.
  - iface validation: HPK non-empty requires every S1-S4 value to be >= 12.
  - Capability gating stays OFF-by-default + report-only drift for the 2.0/3.x
    set (userspace/arm64/client support varies); kernel-module acceptance is now
    verified upstream evidence, client compatibility still varies per app.
  - AdvancedSecurity remains unsupported: the rc=0 result above is unobservable kernel no-op
    acceptance at the pinned source revision, not a stored or active feature.
  - Clearing HPK/S3/S4 on a live interface is not appliable via setconf —
    documented as requiring interface recreate; gated drift remains report-only.
