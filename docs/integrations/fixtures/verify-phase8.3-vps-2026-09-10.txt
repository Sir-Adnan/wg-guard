Phase 8.3 — sanitized Ubuntu 24.04 amd64 Docker verification
Date: 2026-09-10 UTC

Purpose
-------
Close the real-client failure in which AmneziaWG completed a handshake but routed no Internet
traffic. Earlier Phase 8/9 gates reached the tunnel gateway or isolated peer only; they did not
exercise a post-start interface through the host's public route and Docker firewall.

Root causes reproduced
----------------------
1. API/web mutations ran the AWG reconcile engine without refreshing the rendered firewall/NAT
   state, so an interface created after service startup could lack forwarding and masquerade.
2. Docker's iptables backend left `FORWARD` policy `DROP` before WG-Guard's independent nftables
   base chain. Netfilter's terminal drop prevented the later accept rules from taking effect.

The second cause was reproduced both on the dedicated host and in an isolated three-namespace
probe. `ip_forward=1` and WG-Guard masquerade were present while the earlier Docker chain dropped
forwarded packets. A scoped allow through `DOCKER-USER` restored the route without changing the
global policy.

Corrective evidence during the drill
------------------------------------
The first candidate made UFW repair errors fatal but classified a genuinely absent `ufw` binary as
an execution failure. Its install health gate correctly failed. A regression using the real
`exec.ErrNotFound` shape was added and the final candidate passed fresh installation. A later
doctor-only false negative exposed iptables' canonical argument/state ordering and quoted comment
output; the final candidate and fixture use canonical rules and passed doctor plus restart.
Closing fail-safe regressions additionally reject an unparseable host policy, unexpected rules in
WG-Guard's owned child chain and nftables permission failures. These branches do not alter the
verified normal data path and are covered by the final automated gate.
